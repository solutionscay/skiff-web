How it works

Add a project (a Git repository), make worktrees in it, and start agent or shell sessions in each worktree. Sessions sit side by side in named groups. Close the window and the agents keep running. New to this? Read how to run coding agents in parallel. All articles are in Guides.

Sessions outlive the window

A daemon, skiffd, owns every terminal. Close the window and the agents keep working. Open it again and each terminal shows its last screen. An update moves skiffd to the new version and keeps your sessions running. See keeping agent sessions running.

See what needs a look

Each session shows when it waits for you, works or finishes. A finished session gets an unread flag until you go to it.

Projects and worktrees

Sessions sit under the project and worktree they run in. If an agent goes to work in another worktree, the sidebar shows it there too. Start sessions from the project's ⋯ menu or with a right-click on the project. Read the worktree guide.

Groups and layouts

Put related sessions in a named group and split them side by side. Drag a pane by its header to move it.

Themes as location cues

Give each project, group and session its own terminal theme. One look tells you where you are.

Changes, not an editor

Each worktree lists its changed files. Select one to see its diff. A double-click opens the file in the app you pick under Settings › Open with.

The Skiff agent

The Skiff agent is optional. Turn it on in Settings › Skiff agent. Then one agent session, Skipper by default, runs in its own folder, ~/skiff-agent. It sends tasks to sessions in your projects, records them in a SQLite ledger and reports the results to you. The Ledger panel beside its pane sorts the work into Working, Open and Finished. Work moves to Finished when all its tasks are done and reported, or when you tell Skipper to close it. Ctrl+Alt+Shift+L folds the panel to a rail. skiff watch tells Skipper when a session ends a turn, exits or restarts. Its row sits at the top of the side panel. Ctrl+Shift+L shows its pane, and skiff skipper attaches to it from any terminal, an SSH login included. Give it a theme, and while its pane is on screen the side panel and top bar take that theme too.

A project or a fleet can have its own Skipper. Turn them on in Settings › Skiff agent › Project and fleet Skippers. Then select Start project Skipper in the project menu, or Start fleet Skipper in the fleet menu. Skipper hands work to them, and each one changes only its own rows in the Ledger. A project has one Skipper at a time, so a fleet Skipper takes over the project Skippers in its fleet. Hide projects in the fleet menu keeps only the fleet Skipper, the sessions that wait and the session on screen under the fleet head. Show projects brings the rest back. See the Skiff agent page on the wiki.

Images for your agents

Drop an image or a file from another app onto a pane, and Skiff types its path into the pane. Ctrl+Shift+V (⌘V on macOS) does the same with an image or a file list on the clipboard. Ctrl+V stays with the terminal. Skiff keeps a copy of each image in one library. The pane header shows the newest image. Click it to open the library. There you can search by name, session or project, pin an image, or insert its path into the focused pane. To put a path into a different pane, drag the thumbnail onto that pane. Settings › Images shows all the images. Settings › Disk use counts the files in the Skiff agent's folder, and Flush images there removes the images that are not pinned. See the Images page on the wiki.

Small on purpose

Skiff has no plugins, no automations and no hooks into agent configs. It writes nothing into an agent's setup. Settings live in one file, projects.toml. The keyboard and the mouse do the same things, and F1 shows every key.

Install

Skiff ships as .deb, .rpm and AppImage for Linux x86_64, and as a signed .dmg for macOS on Apple Silicon. Go to the downloads.
