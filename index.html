How it works

Add a project (a Git repository), make worktrees in it, and start agent or shell sessions in each worktree. Sessions sit side by side in named groups. Close the window and the agents keep running. New to this? Read how to run coding agents in parallel.

Sessions outlive the window

A daemon, skiffd, owns every terminal. Close the window and the agents keep working. Open it again and each terminal shows its last screen. See keeping agent sessions running.

See what needs a look

Each session shows when it waits for you, works or finishes. A finished session gets an unread flag until you go to it.

Projects and worktrees

Sessions sit under the project and worktree they run in. If an agent goes to work in another worktree, the sidebar shows it there too. Read the worktree guide.

Groups and layouts

Put related sessions in a named group and split them side by side. Drag a pane by its header to move it.

Themes as location cues

Give each project and group its own terminal theme. One look tells you where you are.

Changes, not an editor

Each worktree lists its changed files. A double-click shows the diff. Files open in the apps you pick under Settings › Open with.

Agents

Skiff comes with these agents in Settings. Add any other command line, or start a plain shell. See how Skiff works with Claude Code, Codex, Gemini, Grok and OpenCode.

Small on purpose

Skiff has no plugins, no automations and no hooks into agent configs. It writes nothing into an agent's setup. Settings live in one file, projects.toml. The keyboard and the mouse do the same things, and F1 shows every key.

Install

Skiff ships as .deb, .rpm and AppImage for Linux x86_64, and as a signed .dmg for macOS on Apple Silicon. Go to the downloads.
